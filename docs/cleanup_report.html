Context

What this repository is

The repo implements the ISE 619 project “End-to-End Policy Optimization for Capacity-Constrained Resource Allocation” (Final Report in papers/ISE_619___PROJECT.zip; the math of the bilevel gradient is papers/main.md, identical to after second meeting.tex). It learns a treatment policy from observational logs (Xi, Ti, Yi, êTi(Xi)) under per-arm capacity budgets bt, by maximizing the IPW value V̂IPW(θ) = (1/N) Σi πθ,Ti(Xi)·Yi/êTi(Xi) over the softmax dual-price policy πθ,t(x) = softmaxt((mt,θ(x) − μθ,t)/τ), where the shadow prices μθ ≥ 0 are themselves the argmin of an inner capacity-pricing problem — a bilevel program, differentiated with the implicit function theorem.

The five method families, all present and working:

MethodInner objectiveGradient pathCode
Fsoftmax-weighted Lagrangian F(μ) — non-convex in μscipy L-BFGS-B forward; IFT backward on the augmented KKT systemsrc/inner_F.py
Gconvex log-sum-exp dual G(μ)CVXPYLayer (diffcp); layer size-locked to training Nsrc/inner_G.py
Gssame Gscipy L-BFGS-B + IFT — no cvxpy in the loop, any Nsrc/inner_G.py
Altsame as Fnone — μ refreshed every inner_freq steps and held constant (the dual-refresh idea of the reference paper arXiv:2511.04909, “Dual-Guided Loss”)src/train_alt.py
S2-*two-stage baseline (Tang et al. 2024): fit per-arm outcome models (OLS/lasso/tree/kNN/DR/MLP), solve the sample dual LP for μ̂, deploy argmaxt(m̂t(x) − μ̂t)src/s2_dual.py

Experiments: a snapshot pipeline (generate_data.py → main.py), a queueing-deployment simulator, and four (N × seed) sweep suites (nested synthetic, non-nested synthetic, LaLonde NSW+PSID-1, Criteo Uplift) that produced the figures in the Final Report.

Verification

The math was checked numerically before anything was touched

Every gradient path and identity claimed by the papers was tested against an independent reference on small problems (N=25, T=4, capacities chosen so one arm’s bound is active):

So the two hand-written torch.autograd.Function backward passes (the mathematically riskiest code in the repo) are correct, including with active non-negativity constraints — no gradient bug exists. These checks are now permanent: tests/test_inner_layers.py.

One real mathematical finding: F and G differ on feasibility

Verifying complementary slackness exposed a genuine, previously undocumented asymmetry between the two inner objectives. G’s stationarity condition on inactive coordinates is literally bt = (1/N)Σi πt,i — so the allocation of the G-policy is feasible-in-expectation exactly, with binding arms at capacity to machine precision. F has no such property at finite τ: its stationary point trades the capacity term against the μ-dependence of the softmax weights, and can exceed caps. Measured at the inner optimum of the same score matrix (τ=0.5):

Armcap balloc under μ*Galloc under μ*FF vs cap
10.2500.25000.2496under by 0.0004
20.2000.20000.2152over by 0.0152
30.1500.15000.1687over by 0.0187

This is a property of the objective, not a code bug — and it explains why the experiment harnesses never deploy the raw softmax policy: they either re-price with a sub-capacity buffer (argmax on M − μLP(0.92·b)) or push overflow into the FIFO queue repair layer. It is now stated in the docstrings of src/inner_F.py / src/inner_G.py, the README, and asserted for G in tests/test_inner_layers.py::test_G_complementary_slackness.

Refactor

Modularization: one implementation per idea

The experiment layer had grown by copy-paste: four run_cell_* files ~85% identical, five sweep drivers ~70% identical, three copies of the plotting function, two of the queue-IPW helpers, two data-generator files with byte-identical bodies, and the two IFT backward passes duplicated line-for-line in inner_F/inner_G. Each shared idea now lives in exactly one module:

New moduleSingle home of
src/inner_common.pyL-BFGS-B inner solve + the augmented-KKT IFT backward (ImplicitMu); inner_F/inner_G now supply only their objectives
experiments/common.pyassigners (random / treat-all / oracle / S2 / model+LP-calibrated), Poisson streams, discrete-event queue simulator, row aggregation, IPW helpers, row subsampling, pooled propensity fit
experiments/cell_core.pythe full (N, seed) cell: baselines → F → Alt → Gs → S2 loop → CSV, with resume + failure isolation

The dataset scripts became thin bindings (data loading + cache keys + CLI defaults only), and every historical import path still works — n_sweep_criteo and real_queue_experiment re-export the moved names (_f_arms_and_assigner, _subsample, simulate, …), so the add-on scripts (add_s2_mlp_*, reeval_nonnested_oracle, plotters) run unmodified. Knowledge

What I learned about this project (worth keeping)

  • math The two inner objectives are the same dual up to policy entropy — F ≤ G ≤ F + τ·log|T|, with G−F = (τ/N)ΣiH(σi) verified to 5e−16 — and both collapse to the Tang et al. LP dual as τ→0 (verified against the S2 LP at τ=1e−3). But only G is exactly feasible-in-expectation at finite τ (see the finding above); F buys self-consistency with the deployed softmax at the price of soft capacity violation.
  • math The IFT backward implemented here is the augmented saddle-point system of the Final Report’s Appendix B: [[H+ρI, −EAT],[EA, 0]], which pins dμ*t/dM = 0 on the active set. It matches finite differences even when bounds are active — strict complementarity held everywhere tested.
  • lineage Alt is exactly the “fixed-frequency dual refresh” strategy of the reference paper (Rodriguez-Diaz, Bansak & Paulson, arXiv:2511.04909) transplanted from decision-focused learning to IPW policy learning: it drops the (∂V/∂μ)(dμ/dθ) chain-rule term that F/G compute via the IFT. The repo is therefore a three-way comparison: full implicit differentiation (F, G/Gs) vs dual refresh (Alt) vs decision-blind two-stage (S2).
  • empirics Two deployment conventions coexist and give different wait-time numbers: softmax sampling without buffer (snapshot experiment) vs argmax after re-pricing at 0.92·b (all sweeps). The sub-capacity buffer is what keeps queues short on a finite stream even for an in-expectation-feasible policy.
  • empirics The evaluation convention that matters: μ is part of the trained policy and is never re-solved on eval data. The project tried the eval-μ variant, saw it flatter the results, and reverted it (git history 981c4a9 → 3efaf40); the retired variants are kept only in experiments/legacy/.
  • engineering The warm-start caches in the inner layers are module-global state; the sweeps stay correct only because every cell runs in its own process (maxtasksperchild=1) and make_mu_layer resets state per training run. Documented in sweep_core — worth remembering before ever running cells in-process.
